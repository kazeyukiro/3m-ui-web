# 节点运行状态

节点页把「是否启用」与「是否真正可用」分开展示。主状态徽章表示连通性检测结果（通过 / 失败 / 检测中 / 未测 / 未知 / 已禁用）。**仅有监听套接字并不会显示为可用**。点击节点可打开诊断；在结果仍有效时会复用缓存，否则会对导出的客户端接入点发起检测。保存并启用节点时也会触发检测。详情抽屉会区分：套接字观察、客户端配置、测试客户端启动、认证与代理访问等阶段。

轻量套接字轮询仅在页面可见时进行，**不会**拉起测试客户端。端到端结果在内存中缓存约一分钟；当已应用配置、服务进程或导出的客户端配置变化时会失效。读取缓存时会重新导出当前配置并校验哈希（覆盖公网接入点与有效凭证，且不在缓存中保存含凭证的 YAML）。请求失败会清空展示为未知，而不是继续显示绿色。

## API

使用现有需登录的节点/Listener 路由：

- `GET /api/v1/nodes/runtime-status`：全部本机节点运行状态  
- `POST /api/v1/nodes/:id/check`：对单个节点做一次只读新鲜检测  
- `/api/v1/listeners` 提供相同别名  

列表接口返回数组；单次检测返回单个对象。  
`GET /api/v1/nodes/runtime-status?summary=true` 做相同套接字核查，但 `endpoints` 为空数组，适合页面轮询；打开抽屉或手动检测时再拉完整 endpoints。省略 `summary=true` 时保持完整列表。单次 check 始终返回完整 endpoints。

完整响应示例：

```json
{
  "id": 1,
  "state": "listening",
  "reason": "sockets_bound",
  "checked_at": "2026-01-01T00:00:00Z",
  "endpoints": []
}
```

## 常见状态含义

| 状态倾向 | 含义 |
|----------|------|
| 启用但不可用 | 配置未应用、核心未运行、端口冲突或检测失败 |
| 已应用但未知 | 面板无法访问核心 API 或检测请求失败 |
| 检测通过 | 按导出客户端路径验证可连通（不只是端口在听） |

## 排查建议

1. 确认已 **生成 → 校验 → 应用** 配置  
2. 查看核心日志与面板日志中的 bind / TLS 错误  
3. 检查公网地址、端口与证书是否与导出 URI 一致  
4. 凭证变更后重新检测，避免命中旧缓存  

更细的字段与阶段说明以面板诊断抽屉与 API 返回为准；实现会随版本演进，以当前构建为准。
