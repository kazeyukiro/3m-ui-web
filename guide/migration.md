# 从其他面板迁移

3m-ui 可以读取 3x-ui 与 s-ui 导出的备份，把其中的用户与节点追加导入当前面板，方便迁移。

> 导入是追加操作，绝不替换或覆盖现有数据库。导入前会自动生成一份带时间戳的备份。

## 支持的备份

- 3x-ui：经典 v2（`inbounds.settings.clients`）与拆分表 v3（`client_records` / `client_inbounds`）。
- s-ui：`clients` / `inbounds` / `tls` 表。
- 容器：原始 `.db`、`.zip`、`.gz`、`.tar.gz`；面板自身备份会被识别并提示改用「恢复」。

## 能迁移什么

| 项目 | 说明 |
| --- | --- |
| 用户 | 用户名、凭证、流量上限、已用流量、IP 限制、到期时间、启用状态、备注、分组 |
| 节点 | 协议、端口、监听地址，以及 REALITY / WS / gRPC / XHTTP / TLS 等尽力映射 |
| 绑定 | 用户与节点的关联关系 |
| 流量 | 上传 / 下载字节与流量上限 |
| 跳过 | 不支持的协议（如 WireGuard）与无端口入站会列入「跳过」并说明原因 |

## 导入步骤

1. 打开「设置 → 安全与备份」，在「从其他面板迁移」处选择备份文件。
2. 查看预览：来源、用户 / 节点 / 绑定数量、警告、跳过的条目与待导入节点列表。
3. 阅读「导入前请阅读」的四条提示，点击「确认导入」。
4. 查看结果：创建数量、冲突改名、导入前备份文件名。
5. 到「节点（Listeners）」页面逐一核对导入的节点，再手动启用。

## 重要说明

- 导入的节点默认禁用，状态为 `inactive`，避免未经校对的监听直接生效。
- 3x-ui / s-ui 使用 Xray / sing-box，3m-ui 使用 Mihomo；节点配置是尽力映射，必须人工校对。
- 订阅链接（`sub_token`）会重新生成，客户端需要重新导入订阅。
- 同名用户、同名节点与重复 UUID 会自动改名或重新生成，不会覆盖原有条目。
- 预览接口不写库；导入接口在一个事务内写入，任一步失败都不会留下半成品。
- 自动备份写入数据库同目录的 `backups/pre-migration-*.zip`，可用于回滚。

## 恢复入口的防呆

「恢复」会整库替换，误上传其他面板的备份会破坏当前安装。该入口现在识别 3x-ui / s-ui 备份并返回 HTTP **400**，提示改用迁移导入。

## API

两个接口都要求管理员 JWT，multipart 字段名均为 `database`。

```
POST /api/v1/system/backup/migrate/preview
POST /api/v1/system/backup/migrate/import
```

预览为只读（凭证会打码），导入为追加写入。更多字段见 `openapi.yaml` 与设置页的预览结果。
