# 网站分流与屏蔽

面板可以自定义 Mihomo 规则，实现按网站分流、屏蔽指定站点。规则写在「路由规则」页，按生效位置分为两个范围，写入互不相通：

| 标签 | 生效位置 | 数据去向 |
|------|----------|----------|
| 客户端订阅 | 订阅使用者的设备 | 写入 Mihomo/Clash 订阅的 `proxy-groups` 与 `rules` |
| 服务端出站 | 面板所在的 Mihomo 进程 | 决定流量进入节点后从哪个出口离开 |

同一个屏蔽需求写在哪个范围，取决于要拦谁的访问。拦截自己设备上所有客户端的流量，写在「客户端订阅」；拦截经过面板这条链路的流量，写在「服务端出站」。

## 屏蔽一个网站

Mihomo 用 `REJECT` 出站丢弃匹配的连接。屏蔽单个域名，按精确匹配或后缀匹配写：

```text
DOMAIN,ads.example.com,REJECT
DOMAIN-SUFFIX,tracker.example.com,REJECT
```

批量屏蔽某类站点，用 GEOSITE 分类，例如内置的去广告分类：

```text
GEOSITE,category-ads-all,REJECT
```

规则从上到下匹配，命中即停止。兜底的 `MATCH` 规则必须放在所有屏蔽规则之后，位置错了屏蔽不会生效。

「客户端订阅」范围提供「示例广告域名 → REJECT」模板，可作为起点。规则编辑器右上角的「批量导入」支持一次粘贴多行，后端逐行校验，非法行会标出行号和原因。规则类型与参数以 [mihomo 官方文档](https://wiki.metacubex.one/config/rules) 为准。

## 分流到不同出口

分流的写法是把域名指向策略组，而不是 `REJECT`：

```text
DOMAIN-SUFFIX,example.com,我的节点
GEOSITE,netflix,流媒体组
MATCH,DIRECT
```

策略组在规则编辑器上方的策略组区域维护，节点在「出站管理」中添加。服务端的出站节点也在「出站管理」维护，路由页只负责把它们选作规则目标。规则目标必须真实存在，拼写错误会在生成配置时被核心拒绝。

## 规则如何到达客户端

写在「客户端订阅」范围的规则，保存后进入该用户的订阅。客户端更新订阅即可生效，不需要在设备上另行填写。订阅中策略组的成员会自动替换为当前订阅的节点，服务端专属字段会被剔除。

写在「服务端出站」范围的规则只作用于面板的 Mihomo 进程，不写入任何客户端订阅。两个范围各存各的，不存在相互复制。

使用 GEOSITE 或 GEOIP 规则前，需要在「系统设置 → 反代与 Geo」更新 Geo 数据。
