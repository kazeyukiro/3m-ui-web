Routing & config engine

Switch language in the top bar. Chinese and English article bodies are provided.

Two different things

PageWhat it controls
RoutingClient subscription layout: rules + proxy-groups exported into Mihomo/Clash YAML for users. Also stored in visual-config (and merged into panel core config on generate/apply).
Config engineBuilds the final config.yaml for Mihomo: default template + enabled fragments (including visual-config) + Listeners from the database. Then validate / apply / rollback.

Default is MATCH,DIRECT (minimal). After you set templates/groups, update the subscription in the client to load the new groups — they are not server-only anymore.

How to use Routing

  1. Open Routing in the panel.
  2. Proxy groups: add groups (select / url-test / fallback / load-balance) and list members (DIRECT, outbound names, other groups).
  3. Rules: add rows (type + match value + target). Reorder with up/down. Use Templates for presets (DIRECT only, CN direct, community packs, etc.).
  4. WARP (optional): register Cloudflare WARP into visual-config outbounds and optionally set final MATCH.
  5. Click Save, then Generate & apply (or confirm the prompt) so Mihomo reloads.

Community templates also create matching proxy-groups (e.g. 代理 / AI / TG, or Google / Telegram / 漏网之鱼). Leaf members default to existing outbounds or DIRECT; assign real nodes or WARP into those groups after applying.

GEOSITE/GEOIP templates need MetaCubeX geodata — update under Settings → Geo.

How to use Config engine

  1. Open Config (config engine).
  2. Visual tab: mode / DNS / optional outbound proxies (related to routing).
  3. YAML: Generate builds config from DB (does not write to disk yet). Validate runs mihomo -t. Apply writes config and reloads the core; failure rolls back the previous file.
Edit nodes/users/routing → Generate → Validate → Apply → Core health check
                                      └ on failure: automatic rollback

Creating or editing a Listener also triggers config regeneration; use Config when you need a full preview or manual apply.

Typical workflows

  • Inbound only: leave rules as MATCH,DIRECT; manage nodes under Listeners; use Config only if apply failed.
  • CN direct + rest via group: Routing → template “CN direct” or community YiXuan/echs/MyClash → Save → Apply. Ensure Geo files exist.
  • Exit via WARP: Routing → WARP inject (MATCH to WARP) → Apply.

API (summary)

GET/PUT /api/v1/config/rules
GET/PUT /api/v1/config/groups
POST    /api/v1/config/routing/inject-warp
POST    /api/v1/config/generate
POST    /api/v1/config/validate
POST    /api/v1/config/apply

先分清两件事

页面管什么
路由客户端订阅布局：rules + proxy-groups 会写入用户的 Mihomo/Clash YAML。数据在 visual-config（生成并应用时也会进入面板核心配置）。
配置引擎生成最终给 Mihomo 的 config.yaml：默认模板 + 启用的配置片段（含 visual-config）+ 数据库里的 节点 Listener。再校验 / 应用 / 失败回滚。

默认 MATCH,DIRECT。在路由页配置模板/策略组后，请在客户端更新订阅即可看到对应策略组（不再只是服务端分流）。

路由怎么用

  1. 打开面板 路由。
  2. 策略组：新建 select / url-test / fallback / load-balance，成员可写 DIRECT、出站名、其它组名。
  3. 规则：按行编辑（类型 + 匹配值 + 目标），可上移下移。用 模板 一键填入（仅直连、国内直连、社区模板等）。
  4. 可选 WARP：注册 Cloudflare WARP 写入出站，并可选改最终 MATCH。
  5. 点 保存，再在弹窗里 生成并应用（或点 Apply），Mihomo 才会加载新规则。

社区模板会一并写入对应的策略组（如 代理 / AI / TG，或 Google / Telegram / 漏网之鱼），不是只有规则。叶子成员默认用已有出站或 DIRECT；应用后请把真实节点或 WARP 填进各组。

带 GEOSITE/GEOIP 的模板需要 MetaCubeX 地理数据：在 系统设置 → Geo 更新。

配置引擎怎么用

  1. 打开 配置引擎。
  2. Visual：模式 / DNS / 可选出站代理（与路由相关）。
  3. YAML：生成只根据数据库拼出配置（还不落盘）；校验跑 mihomo -t；应用写入配置并重载核心，失败会回滚上一份文件。
改节点/用户/路由 → 生成 → 校验 → 应用 → 核心健康检查
                         └ 失败：自动回滚

在 节点管理 里增删改 Listener 一般也会触发生成；需要完整预览或手动发布时再进配置引擎。

常见用法

  • 只做入站：规则保持 MATCH,DIRECT；日常只管节点；配置引擎仅在应用失败时排查。
  • 国内直连、其余走策略组：路由 → 模板「国内直连」或社区 YiXuan / echs / MyClash → 保存 → 应用。先更新 Geo。
  • 出口走 WARP：路由 → WARP 注入（MATCH 到 WARP）→ 应用。
