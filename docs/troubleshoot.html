Troubleshooting

Switch language in the top bar. Chinese and English article bodies are provided.

Troubleshooting

  • systemctl status 3m-ui / journalctl -u 3m-ui -n 100
  • Confirm panel port is listening and not blocked by firewall
  • After password change, use the new password; session tokens rotate with session_version
  • Mihomo config validation errors appear when applying listeners — fix fields and re-apply
  • If create/delete shows a network error but the list already changed: the panel wrote the DB first and applies Mihomo in the background. Refresh the list and wait 1–2 seconds; this is expected, not a failed save.
  • Disk full / large /var/lib/3m-ui/backups: install snapshots accumulate. Use Settings → Backup → Cleanup (or API POST /system/backups/cleanup). See Backup & restore.
  • Update rolls back with uidx_user_hwid already exists: fixed in recent builds — update again after CI ships the fix. The panel drops the legacy HWID index before migrate.

Web UI unreachable — SSH rescue

If you locked yourself out of the web UI (panel bound to 127.0.0.1, wrong port, broken SSL config), SSH into the server and run 3m-ui reset-config to roll back to safe defaults. The panel restarts in plain HTTP mode so you can re-apply settings from the browser.

Quick rescue (most common)

sudo 3m-ui reset-config --panel --yes
# stop → clear server.listen + disable SSL → restart in HTTP mode

Then open http://<server-ip>:<port>/ (HTTP, not HTTPS) and re-apply your SSL / public_url / access_profile settings from the UI.

Scope flags

FlagWhat it resets
--panel (default)server.listen (→ :<port>) + disable ACME/SSL. Port preserved.
--accessClear listener.public_host / access_sni / access_alpn on all listeners.
--publicClear server.public_url (subscription falls back to request host).
--allApply all three scopes above.
--yes / -ySkip interactive y/N prompt (for rescue scripts).

Interactive menu

sudo 3m-ui        # open the menu, choose option 16

The menu walks you through scope selection (1/2/3) and confirmation, then stops/runs the binary/restarts the panel automatically.

What it never touches

  • Users, listeners, traffic records, credentials
  • The SSL domain / cert paths (only the Enabled flag is flipped so you can re-enable from the UI after fixing the underlying issue)
  • The server port (preserved so SSH rescue doesn't require re-reading the YAML)

Re-enable SSL after rescue

Open the panel over HTTP, go to Settings → SSL, fix the underlying issue (e.g. wrong domain, missing 80/443 access), then toggle SSL back on. The previously-saved domain / cert files are still in the DB, so you only need to flip the switch.

面板无法启动

端口被占用

lsof -i :8080
# 或
ss -tlnp | grep 8080

解决：释放端口或修改面板端口：

3m-ui config port 9000

配置文件无效

检查 /etc/3m-ui/config.yaml：

cat /etc/3m-ui/config.yaml

JWT Secret 和 Credential Key 必须是 32+ 字节的随机值。如果使用了占位符 CHANGE_ME_TO_RANDOM_32_PLUS_BYTES 或默认值，面板会拒绝启动。

生成新密钥：

openssl rand -hex 32

数据库恢复后无法启动

恢复备份后必须重启面板：

systemctl restart 3m-ui

如果恢复的是损坏的数据库文件，删除后重新恢复：

systemctl stop 3m-ui
rm /var/lib/3m-ui/3m-ui.db
# 重新上传备份恢复
systemctl start 3m-ui

Mihomo 核心问题

核心无法启动

3m-ui logs  # 查看面板日志
journalctl -u 3m-ui -n 50  # 查看系统日志

常见原因：
- 配置文件语法错误（面板会自动回滚到上一个有效配置）
- 端口冲突（检查 listener 端口是否被占用）
- 二进制路径不正确（检查 config.yaml 中的 mihomo.binary）
- Mihomo 二进制缺少执行权限

核心崩溃

面板会自动检测核心崩溃并通过 Telegram 通知（如已启用 crash 事件）。自动重启会在配置验证通过后尝试。

磁盘占满 / backups 过大

安装与更新快照会堆在 /var/lib/3m-ui/backups。在面板 设置 → 备份 使用「清理备份」，或调用 POST /api/v1/system/backups/cleanup。说明见 备份与恢复。

更新失败回滚（uidx_user_hwid already exists）

旧 HWID 表索引与新表冲突。请使用已修复的版本再次 3m-ui update（启动前会清理遗留索引）。

流量数据不更新

检查 Mihomo external-controller 是否正常：

curl -H "Authorization: Bearer <secret>" http://127.0.0.1:9090/connections

如果返回空或错误，核心可能未正常运行。

Telegram Bot 问题

Bot 不响应

  1. 检查 Token 是否正确（在面板「系统设置 → Telegram 通知」中重新输入）
  2. 检查 Bot 是否被禁用
  3. 查看 journalctl -u 3m-ui 中是否有 telegram: getUpdates 错误
  4. 401 错误表示 Token 无效，Bot 会每 5 分钟重试一次

Bot 命令菜单不显示

点击面板中的「注册命令菜单」按钮，或调用：

curl -X POST -H "Authorization: Bearer <token>" \
  https://panel.example.com/api/v1/telegram/set-my-commands

订阅问题

订阅链接返回 404

Token 可能已轮换。在「用户管理」中重新获取订阅链接。

订阅内容为空

检查用户是否绑定了至少一个启用的 Listener。在「用户管理 → 绑定节点」中确认。

集群问题

远程操作返回 401

集群的 api_token 必须是远程面板签发的 JWT（不是 Access Token）。获取方式：

curl -X POST https://remote-panel.com/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<password>"}'

返回的 token 字段即为 JWT，填入集群设置的 api_token。

创建/删除节点提示失败，但列表已变化

节点与用户变更会先写面板数据库并立即返回，Mihomo 配置在后台短延迟后应用。浏览器若在重载期间断连，可能看到「无法连接面板 API」类提示，但刷新列表后节点已存在或已删除。属预期行为：等 1～2 秒再测连通性即可。

远程健康检查超时

多个远程服务器会并行健康检查。如果某个服务器网络不稳定，可能需要增加超时时间或检查网络连接。

Web 面板无法访问 — SSH 救援

如果面板配置错误（绑了 127.0.0.1、端口错、SSL 配置错）导致 Web 完全打不开，SSH 进服务器运行 3m-ui reset-config 即可回滚到安全默认值。面板会以纯 HTTP 模式重启，方便你在浏览器里重新配置。

快速救援（最常用）

sudo 3m-ui reset-config --panel --yes
# 停止 → 清空 server.listen + 关闭 SSL → 以 HTTP 模式重启

然后用 http://<server-ip>:<port>/（HTTP，不是 HTTPS）打开面板，重新应用 SSL / public_url / access_profile 设置。

作用域参数

参数重置什么
--panel （默认）server.listen（→ :<port>）+ 关闭 ACME/SSL。端口保留。
--access清空所有节点的 listener.public_host / access_sni / access_alpn。
--public清空 server.public_url（订阅链接回退到请求 Host）。
--all同时应用上述三个作用域。
--yes / -y跳过交互式 y/N 确认（适合脚本）。

交互式菜单

sudo 3m-ui        # 打开菜单，选择 16

菜单会引导你选作用域（1/2/3）并确认，然后自动停止 → 调 binary → 重启面板。

绝对不会动的东西

  • 用户 / 节点 / 流量记录 / 凭证
  • SSL 的域名 / 证书路径（只翻 Enabled 开关，方便你在 UI 修完底层问题后一键重新启用）
  • 面板端口（保留，SSH 救援不需要重读 YAML 找端口）

救援后如何重新启用 SSL

用 HTTP 打开面板 → 系统设置 → SSL，修好底层问题（比如域名填错、80/443 端口没放行），然后重新打开 SSL 开关。域名 / 证书文件都还在数据库里，只需要扳一下开关。
